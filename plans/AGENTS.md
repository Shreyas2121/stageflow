The phase file defines the contract; its guide defines the implementation sequence and commit discipline. A new user request may authorize maintenance independently of outstanding physical observations. Do not start future phases just because a plan or roadmap exists.

For a requested V2 review slice, consult its finding and maintenance entry in the optional root `review.md`, then current code and Git history. Recent maintenance evidence is appended to the corresponding V2 contract; historical phase/guide results are not proof of a later patch. Record actual commands, commit hashes and observation limits. Preserve earlier records and explicitly open physical/native-picker observations; a synthetic or controlled-browser result does not close them.

Keep AGENTS files limited to navigation and durable rules. Put task results and acceptance history here. Documentation-only work needs changed-file formatting and path/link checks, not repeated application suites. Do not revise plan scope or mark acceptance passed merely to make a gate appear complete.
